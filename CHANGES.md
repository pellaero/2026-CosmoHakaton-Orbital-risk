# Правки в eva_app.py

Исходный скрипт запускается, но из-за устаревших адресов API и двух ошибок в логике
для любой даты, кроме 11.05.2024, он молча работает на встроенных данных 2024 года
(LocalDataSnapshot). В результате отчёт выглядит правдоподобно, но для текущих дат он неверный.

## Мёртвые адреса данных (сейчас отдают 404)

1. **TLE МКС** (`fetch_tle_robust`)
   `celestrak.org/NORAD/elements/stations.txt` → `celestrak.org/NORAD/elements/gp.php?CATNR=25544&FORMAT=tle`
   Раньше орбита всегда бралась из снапшота с эпохой 2024 года, поэтому тень и блики для текущих дат считались неверно.

2. **Протоны >10 МэВ** (`fetch_proton_data`)
   `services.swpc.noaa.gov/products/goes/proton-flux-7-day.json` → `services.swpc.noaa.gov/json/goes/primary/integral-protons-7-day.json`
   У нового эндпоинта другой формат: список объектов `{time_tag, flux, energy}`. Фильтруем по `energy == ">=10 MeV"`.
   NOAA хранит только последние 7 дней. Если за выбранную дату данных нет, используется снапшот (как раньше).

3. **MMOD / SOCRATES** (`fetch_mmod_socrates`)
   `celestrak.org/SOCRATES/data/scr.txt` → `celestrak.org/SOCRATES/sort-minRange.csv`
   Парсер переписан под CSV:
   - берутся только сближения с МКС (NORAD 25544 в любой из колонок);
   - заполняется поле `tca`. Раньше его не было, и `calculate_advanced_risk` упал бы с `KeyError: 'tca'`, как только SOCRATES ответил бы;
   - отбрасываются записи с относительной скоростью < 0.01 км/с. Это пристыкованные корабли (Союз МС-29 числится как «сближение» на 6 м); без фильтра MMOD срабатывал бы всегда.

## Ошибки в логике

4. **Исторический режим никогда не включался** (`fetch_kp_data`)
   Код проверял `mode == "Исторический"`, а радиокнопка передаёт `"Исторический режим (Replay)"`.
   Исправлено на `mode.startswith("Исторический")`. Теперь реальный архив Kp грузится из GFZ Potsdam.
   До исправления для 11.05.2024 Kp не учитывался вообще (базовый риск 0/100 в день экстремальной бури).

5. **Режим «Прогноз на 3 дня» не использовал прогноз** (`run_analysis`)
   Прогноз `get_kp_forecast()` загружался, но в расчёт шёл `kp_df` за дату из поля ввода.
   Теперь в расчёт идёт прогноз Kp, а протоны берутся на текущую дату.

6. **Неверный вывод в отчёте прогноза**
   При риске 0/100 печаталось «Ситуация критическая». Добавлена ветка «Обстановка спокойная» для риска < 40.

## Запуск (Docker)

```
docker compose up -d --build
```
(подробности — в README.md)
→ http://127.0.0.1:7860

В Dockerfile при сборке `server_name` меняется с 127.0.0.1 на 0.0.0.0 (иначе приложение недоступно из-за пределов контейнера),
а эфемериды `de421.bsp` скачиваются заранее.

## Проверено

Все три режима (исторический 2024-05-11, текущая обстановка, прогноз на 3 дня) отрабатывают без ошибок,
строят отчёт, график и JSON. Для 2024-05-11 окно 12:00 даёт 70/100 (протоны 45.2 pfu + Kp 8.7), окно 18:00 даёт 30/100.

## Не исправлено (на заметку)

- В прогнозе на 3 дня перебираются окна с шагом 1 час только на 48 ч вперёд, а в отчёт выводятся только первые 3 из них (все сегодня, 00:00–02:00).
## Новый интерфейс (по дизайну «EVA Current UI Restyled» из Claude Design)

Логика расчёта не менялась: `run_analysis` и всё, что выше раздела «8. ИНТЕРФЕЙС GRADIO», осталось как было
(добавлены только импорты `html`, `re`, `os`, `base64`). Переписан только раздел 8:

- Тёмная тема: акцент #FF5A13, шрифты Manrope и Azeret Mono (Google Fonts), фон Земли из `static/bg.jpg`
  (встраивается в CSS при старте), полупрозрачные карточки с размытием фона.
- `run_analysis_ui` — обёртка над `run_analysis`: текстовый отчёт разбирается и отображается карточками
  (окна, флаги-чипы, рекомендация, сравнение с T5, доказательная база); график Plotly перекрашивается в палитру
  дизайна (`style_chart`); статус кэша выводится списком (`cache_to_html`).
- В переключателе режима видимые подписи сокращены («Исторический (Replay)»), но значения,
  которые получает логика, остались прежними.
- `theme`/`css`/`head` передаются в `launch()` (требование Gradio 6, убирает предупреждение).
- Dockerfile: добавлено `COPY static ./static`.
- Адаптивность: на ширине < 900 px колонки идут одна под другой.

Если формат текстового отчёта в `run_analysis` поменяется, нужно обновить `_parse_report`.
